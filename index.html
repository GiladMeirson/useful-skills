the format

A skill is a folder your agent reads before it works.

One SKILL.md describing when to use it and how, plus optional reference documents and helper scripts it opens only when the task calls for them. No build step, no configuration, no runtime.

The format is not Anthropic-specific any more. Claude Code reads skills from .claude/skills/; GitHub Copilot reads .github/skills/ — and also .claude/skills/, which means a repository that already has Claude Code skills needs no second copy for Copilot's coding agent, CLI, or agent mode in VS Code and JetBrains. Same frontmatter, same Markdown, same folder.

Where a skill goes
ScopeClaude CodeGitHub Copilot
project .claude/skills/<name> .github/skills/<name>
global ~/.claude/skills/<name> ~/.copilot/skills/<name>

"Global" means your user folder — on Windows that is C:\Users\<you>\.claude\skills\. The installer resolves it for you and prints the full path before it writes anything.

What survives the port
SkillClaude CodeGitHub CopilotWhy
canvas-atelier ● full ● full Pure technique. No host APIs — it only needs some way to look at the rendered pixels.
physics-2d ● full ● full Plain CommonJS modules plus reference docs. Nothing host-specific anywhere in it.
caveman ● full ● full Response style only. /caveman is Claude Code's slash form; on Copilot the plain words work, or add a prompt file.
matrix-agents-skill ● full ◐ adapted Resolves the host's skills directory and memory file at runtime. Copilot has no AskUserQuestion and no hooks, so the interview runs as chat and the trigger word carries the weight.
skill-report ● full ◐ best-effort The footer is portable; the guarantee is not. Its Stop hook reads the transcript, and Copilot has no post-turn interception point at all.

The two ◐ rows are honest, not hedged: both skills ship a references/ file spelling out exactly what degrades on Copilot and what to add to .github/copilot-instructions.md to compensate.

01

        

          rendering plate 01 / 05
          
canvas-atelier

          

            Gallery-quality drawing and animation on HTML canvas: construction-based form,
            physically-based light, organic curves instead of primitives, and motion that carries weight.
          

        


        

          

            Most canvas drawings look like clip art, and the reason is process, not code.
          


          

            

              A trained illustrator never draws final lines first — the work moves through stages, and
              each stage catches a mistake the next one would otherwise bake in permanently. Jump
              straight from idea to final shapes and you get the flat, symmetric, sterile look that
              gives generated art away at a glance.
            

          

          

            

              This skill encodes that process as nine stages, and hands the agent the reference
              material and helper code for each one. Its sharpest opinions: pick one
              light direction and make every highlight and shadow agree with it; shade with a darker,
              desaturated version of the local hue rather than black; derive the shadow's warmth from
              the light's own temperature; put peak saturation at the core-shadow transition rather
              than the highlight; and never finish without rendering the image and actually looking
              at it, because gradient math and compositing order fail in ways that are invisible
              in source and obvious in pixels.
            

          

          

            

              It also assumes something unusual about who is drawing. An illustrator types no
              coordinates at all — they put a mark down, look at it, and move it.
              bezierCurveTo(340, 210, …) is dead reckoning in an invisible coordinate
              system, and independently guessed features don't cancel their errors, they accumulate.
              So the skill leans on the one faculty that survives not being able to see: it
              computes. Gradient stops are sampled from surface normals rather than picked by
              eye; landmarks are derived from a rig so an eye cannot drift off a head; proportions are
              asserted and throw before a pixel is drawn; and the critique stage looks at the
              silhouette, the mirror image and the blur, not just the straight render.
            

          


          

            

              Drawn, not assembled
              

                
                
                
              

            

            

              
              

                
                
                
                
                
                
                
              

            

            

          


          

            

              Verlet silk, shaded by fold curvature
              drag the banner
            

            

              
            

            

              Connected points can't be animated one eased curve at a time — they come apart. This is
              Verlet integration with distance constraints, the approach in the skill's
              references/physics-motion.md, with each quad shaded by how far its own
              surface has turned from the light. That local-normal shading is the difference between
              lit cloth and a moving wireframe.
            

          


          

            The workflow, rendered: same subject, five stages
            

              
1 · block-in

              
2 · contour

              
3 · light

              
4 · texture

              
5 · finish

            

            

              Proportion first with flat primitives; primitives replaced by asymmetric beziers; one
              light direction with core shadow, cast shadow and bounce light; noise to break the plastic
              smoothness; then the specular hit, stalk and rim light. Skipping to stage five is what
              produces clip art.
            

          


          

            

              One light, and everything else solved from it
              drag the key
            

            

              
              

                
                
                
                
                
                
                
                
              

            

            

              Nothing here is re-authored when the light moves. Every gradient stop is sampled from the
              surface normal at that point, so the terminator lands where N·L crosses zero
              rather than where a stop was dragged to; the cylinder's terminator stays a straight line
              because its normal does not vary with height, which is the reason
              cylinderGradient exists separately from sphereGradient. Take the
              key out to the rim and it drops toward grazing: the shadows stretch by 1/Lz,
              the light warms to about 2300 K and the shadows cool to the complement, because shadow
              temperature is derived from the light's rather than fixed at blue. The four buttons after
              render are stage nine, the critique contact sheet: the same passes an art
              director looks at instead of trusting the eye that placed the forms.

              In practice
              

                

                  You type
                  
Draw a realistic red apple on a wooden table.

                

                

                  What changes
                  
Without the skill: two arc() calls, a flat red fill, a brown rectangle, a grey ellipse for shadow.

                  
With it: the canvas is sized for real pixel density first; the apple is blocked in at low opacity to check proportion; every contour becomes a slightly asymmetric bezier; one light direction drives a multi-stop gradient with a core shadow, a cast shadow that follows the table's angle and bounce light on the shadow side; a noise layer breaks the plastic sheen; a pinpoint specular lands last. Then it renders the image and checks it against a critique list before calling it done.

                

              

              

                Triggers on any request to draw, illustrate, render, sketch or animate
                on canvas — and on words like "realistic", "polished" or "professional" — without
                needing the skill named.

02

        

          simulation plate 02 / 05
          
physics-2d

          

            A small, tested rigid-body engine, plus the reasoning behind every choice in it — for when
            motion has to be simulated rather than scripted.
          

        


        

          

            Hand-rolled game physics is usually wrong in ways that only surface later.
          


          

            

              Objects gain energy and vibrate, stacks explode or sink into the floor, fast objects pass
              through walls, nothing ever comes to rest. None of that is bad luck — each is a specific
              known mistake with a specific known fix, and this skill ships an engine that already makes
              the right call, with reference documents explaining why so the engine can be extended or
              debugged rather than treated as a black box.
            

          

          

            

              The choices it argues for: velocity before position (semi-implicit Euler, or energy leaks
              in and the simulation detonates); a fixed timestep accumulator rather than the raw frame
              delta; two contact points for a resting box via face clipping, or it
              rocks; clamping the accumulated impulse rather than each increment, so resting
              contacts reach true zero; split-impulse position correction instead of a Baumgarte bias,
              which injects energy; a slop tolerance so contacts don't flicker; and raycasting rather
              than substepping to stop a fast bullet.
            

          


          

            

              The actual engine
              bodies —
            

            

              
              

                
                
                
                
                
                drag a body · click empty space to fire
              

            

            

              This runs the engine itself, not an approximation of it: SAT with face clipping for
              two-point manifolds, a block solver that resolves both points of a contact simultaneously,
              Coulomb friction, revolute joints for the chain, a real world.raycast for the
              aiming line, and island-based sleeping — watch the "asleep" counter climb as the pyramid
              settles, then drop the moment you disturb it.

              In practice
              

                

                  You type
                  
Crates that stack up, and a cannon to knock them over.

                

                

                  What changes
                  
Without the skill: boxes that jitter forever, sink into the ground, and explode when the tab is backgrounded.

                  
With it: a World with gravity and a static floor, box bodies with friction and restitution, everything driven by world.update(dt) on a fixed step with interpolated rendering, and the cannon wired to world.raycast. The pile settles, stays settled, and goes to sleep.

                

              

              

                Pairs with canvas-atelier. This is the "does it behave correctly" half.
                Soft connected motion — cloth, hair, rope — belongs to the Verlet approach in
                canvas-atelier. Simulate rigid bodies here, drape soft detail there.

03

        

          output style plate 03 / 05
          
caveman

          

            Cuts the padding out of every reply and keeps all of the substance. Its own frontmatter
            claims a measured 65% reduction in output tokens.
          

        


        

          

            What it refuses to touch is the part that makes it safe to leave on.
          


          

            

              The skill drops articles, filler ("just", "basically", "actually"), pleasantries and
              hedging, and allows fragments. Anything load-bearing survives untouched: technical terms
              stay exact, code blocks are untouched, error strings are quoted verbatim, and API and CLI
              names are never abbreviated. It also refuses to invent abbreviations like cfg
              or impl — the tokenizer splits those the same as the full word, so they save
              nothing and cost the reader clarity.
            

          

          

            

              It runs at four intensities plus classical-Chinese (wenyan) variants, preserves
              whatever language you wrote in, and drops back to normal prose automatically
              for security warnings, irreversible action confirmations, and any multi-step sequence
              where dropped conjunctions would make the order ambiguous. Compression is never allowed to
              create doubt about whether to back up before dropping a table.
            

          


          

            

              Same answer, four intensities
              
            

            

              

                

                  
Question

                

                

                  
                  
                  
                  
                

                

                

              

            

            

              Percentages are measured against the "off" answer with a rough token heuristic. Notice
              what survives all the way to ultra: useMemo, the actual cause, the actual
              fix. What disappears is everything that was never information.

                It stays on until you stop it, across every turn of the session, and it
                answers in whatever language you asked in: write Portuguese and you get Portuguese
                caveman. The last two phrases are the only off switches, and it drops back to full prose
                by itself for security warnings and irreversible-action confirmations without being told.

              /caveman in Copilot Chat, add one prompt file:

              What ships in the folder

                and the next session already knows the phrases above.
              

            

            

              Intensities

04

        

          meta plate 04 / 05
          
matrix-agents-skill

          

            Watches a session for knowledge worth keeping, and turns the best of it into a new skill.
            The machine that builds machines.
          

        


        

          

            Every session creates knowledge and then throws it away.
          


          

            

              How a flow actually works, why one fix broke something else, which convention the project
              settled on. This skill runs quietly in the background of ordinary work, appending a line
              to a tally file after each completed task whenever it matches one of eleven patterns
              across five families — repetition, pain, exploration, decisions, and environment quirks.
              It writes the tally down rather than trying to remember, because attention decays over a
              long session and counts get lost.
            

          

          

            

              The restraint is the design. It never interrupts mid-task; when a pattern crosses its
              threshold it emits exactly one line and keeps working. At the end it proposes
              at most one skill — the strongest candidate, ranked pain over exploration
              over decisions over repetition — and only if the result would save a future session real
              work. Say no and the topic goes in a declined.md it never raises again. Say
              yes and the gate opens onto a real interview, including the question that matters most:
              was anything here an exception that should not become the rule?
            

          


          

            

              A session in fast-forward
              
            

            

              

              

                

                

              

            

            

              Real patterns and real thresholds from the skill's table. Four styling fixes trip pattern
              #1; two regressions in a row trip #4. Both are candidates, but only one gets proposed —
              pain outranks repetition, because knowledge bought with a regression saves the most time
              later.
            

          


          

            

              What ships in the folder
              
    
                
  • SKILL.mdThe eleven-pattern table with thresholds, the interview question bank, the generated-skill format, and the routing-map block it maintains in the host's memory file
    • 
                
  • host-agents.mdHow it detects which agent it is running under, and the full Claude Code ↔ Copilot mapping for skills directory, memory file, question UI and enforcement
    • 
              

              

                Creates two files as it runs, not shipped with it:
                session-tally.md (deleted after each proposal) and declined.md.
                It also delegates the actual writing to Anthropic's skill-creator skill
                when that's installed, rather than hand-rolling the format.
              

            

            

              Why it registers what it builds
              

                

                  The routing map
                  
A skill nobody routes to may as well not exist. After every skill it creates, it updates a delimited block in the host's always-loaded memory file — CLAUDE.md, .github/copilot-instructions.md, or AGENTS.md — one line per skill, in the form "trigger condition → path".

                  
Because that file loads in every session, the block guarantees a future session knows which skills exist without loading any of them. If a repo has more than one, it writes to each: teams run both agents against the same code.

                

                

                  Trigger words
                  
/forge · /matrix · forge · matrix · פורג' · מטריקס

          transparency plate 05 / 05
          
skill-report

          

            A one-line footer on every reply naming which skills, subagents and web tools actually ran —
            read from the transcript, not from the model's memory of what it did.
          

        


        

          

            Asking a model to recall its own tool use invites a confident, wrong answer.
          


          

            

              Skills fire at the agent's discretion, which makes it genuinely hard to tell whether the
              one you installed did anything. This skill answers that question on every single turn.
              The detail that makes it trustworthy is where the answer comes from: a Stop hook reads the
              session transcript and extracts the real Skill, Agent,
              WebSearch and WebFetch calls. The transcript is ground truth.
            

          

          

            

              A skill alone can't guarantee it fires every turn, so this one is paired with a hook that
              checks for the footer and forces one continuation if it's missing — which is why the
              report is unconditional rather than best-effort. Routine tools are deliberately excluded:
              Read, Edit, Bash and Grep run on nearly every turn, and listing them would turn signal
              into noise. The footer surfaces delegated capability.
            

          


          

            

              One turn, and the footer it produces
              
            

            

              

            

            

              Greyed calls are the routine tools the hook ignores on purpose. Note the third turn: when
              nothing was delegated, the footer still appears and says none three times —
              an honest negative is the whole point.
            

          


          

            

              What ships in the folder
              
    
                
  • SKILL.mdThe footer format, the host support matrix, and why a hook is required for it to be unconditional
    • 
                
  • scripts/report_hook.pyThe Stop hook — parses the transcript, finds this turn's real tool calls, forces a continuation when the footer is missing, and refuses to loop more than once
    • 
                
  • github-copilot.mdWhat degrades under Copilot, the exact instruction block to paste, and why no Copilot equivalent of the hook can exist
    • 
              

            

            

              One extra step
              

                Copying the folder is not enough for this one — on Claude Code the hook has to be
                registered in your project's .claude/settings.json. Merge this in, adding
                to an existing Stop array if you already have one.
              

              

                
{
  "hooks": {
    "Stop": [
      { "hooks": [ { "type": "command",
        "command": "python \"$CLAUDE_PROJECT_DIR/.claude/skills/skill-report/scripts/report_hook.py\"",
        "timeout": 15 } ] }
    ]
  }
}

                
              

              

                Under GitHub Copilot there is no hook to register — no post-turn interception point
                exists — so the footer becomes a standing line in
                .github/copilot-instructions.md and is best-effort by construction.
