How this works

A skill is a folder Claude reads before it works.

One SKILL.md describing when to use it and how, plus optional reference documents and helper scripts it opens only when the task calls for them. Put the folder in .claude/skills/ and Claude finds it on the next session — no build step, no configuration, no restart beyond starting a new session.

Install any skill 
npx degit GiladMeirson/useful-skills/skills/<name> .claude/skills/<name>

Needs only npx, which ships with Node — already a Claude Code prerequisite. It copies one folder, not the whole repository. Run it from your project root, or install to ~/.claude/skills/<name> to make a skill available in every project. Each skill below has this line filled in and ready to copy.

01 — rendering

canvas-atelier

Gallery-quality drawing and animation on HTML canvas: construction-based form, physically-based light, organic curves instead of primitives, and motion that carries weight.

Most canvas drawings look like clip art, and the reason is process rather than code. A trained illustrator never draws final lines first — the work moves through stages, and each stage catches a mistake the next one would otherwise bake in permanently. Jump straight from idea to final shapes and you get the flat, symmetric, sterile look that gives generated art away at a glance.

This skill encodes that process as eight stages, and hands Claude the reference material and helper code for each one. Its sharpest opinions: pick one light direction and make every highlight and shadow agree with it; shade with a darker, desaturated version of the local hue rather than black; derive the shadow's warmth from the light's own temperature; put peak saturation at the core-shadow transition rather than the highlight; and never finish without rendering the image and actually looking at it, because gradient math and compositing order fail in ways that are invisible in source and obvious in pixels.

Live · Verlet silk, shaded by fold curvature drag the banner

Connected points can't be animated one eased curve at a time — they come apart. This is Verlet integration with distance constraints, the approach in the skill's references/physics-motion.md, with each quad shaded by how far its own surface has turned from the light. That local-normal shading is the difference between lit cloth and a moving wireframe.

The workflow, rendered — same subject, five stages
1 · block-in
2 · contour
3 · light
4 · texture
5 · finish

Proportion first with flat primitives; primitives replaced by asymmetric beziers; one light direction with core shadow, cast shadow and bounce light; noise to break the plastic smoothness; then the specular hit, stalk and rim light. Skipping to stage five is what produces clip art.

What ships in the folder
  • SKILL.mdThe eight-stage workflow and a "do this, not that" table
  • composition.mdFocal point, selective fidelity, depth, negative space
  • lighting-and-shading.mdCore / cast / ambient-occlusion / rim model with gradient code
  • organic-curves.mdTurning primitives into believable asymmetric contours
  • color-theory.mdShadow temperature and where saturation should peak
  • precision-and-form.mdPerspective, value before colour, lost-and-found edges
  • animation-principles.mdEasing, squash and stretch, anticipation, arcs, follow-through
  • physics-motion.mdVerlet for cloth, hair, rope, flags
  • scripts/canvas-setup, easing, bezier-utils, noise, verlet
In practice
You type

Draw a realistic red apple on a wooden table.

What changes

Without the skill: two arc() calls, a flat red fill, a brown rectangle, a grey ellipse for shadow.

With it: the canvas is sized for real pixel density first; the apple is blocked in at low opacity to check proportion; every contour becomes a slightly asymmetric bezier; one light direction drives a multi-stop gradient with a core shadow, a cast shadow that follows the table's angle and bounce light on the shadow side; a noise layer breaks the plastic sheen; a pinpoint specular lands last. Then it renders the image and checks it against a critique list before calling it done.

Triggers on any request to draw, illustrate, render, sketch or animate on canvas — and on words like "realistic", "polished" or "professional" — without needing the skill named.

02 — simulation

physics-2d

A small, tested rigid-body engine, plus the reasoning behind every choice in it — for when motion has to be simulated rather than scripted.

Hand-rolled game physics is usually wrong in ways that only surface later: objects gain energy and vibrate, stacks explode or sink into the floor, fast objects pass through walls, nothing ever comes to rest. None of that is bad luck — each is a specific known mistake with a specific known fix, and this skill ships an engine that already makes the right call, with reference documents explaining why so the engine can be extended or debugged rather than treated as a black box.

The choices it argues for: velocity before position (semi-implicit Euler, or energy leaks in and the simulation detonates); a fixed timestep accumulator rather than the raw frame delta; two contact points for a resting box via face clipping, or it rocks; clamping the accumulated impulse rather than each increment, so resting contacts reach true zero; split-impulse position correction instead of a Baumgarte bias, which injects energy; a slop tolerance so contacts don't flicker; and raycasting rather than substepping to stop a fast bullet.

Live · the actual engine bodies —
drag a body · click empty space to fire

This runs the engine itself, not an approximation of it: SAT with face clipping for two-point manifolds, a block solver that resolves both points of a contact simultaneously, Coulomb friction, revolute joints for the chain, a real world.raycast for the aiming line, and island-based sleeping — watch the "asleep" counter climb as the pyramid settles, then drop the moment you disturb it.

What ships in the folder

  • index.jsOne entry point over all nine modules
  • world.jsFixed timestep, sleeping, anti-tunneling, filtering
  • collision.jsSAT narrow phase and contact manifolds
  • solver.jsAccumulated impulses, restitution, friction, split correction
  • constraints.jsDistance, revolute and spring joints
  • raycast.jsHitscan, line of sight, picking, swept CCD
  • broadphase.jsSpatial hash culling the O(N²) pair test
  • selftest.jsNode smoke tests — free-fall, stacking, friction, joints
  • demo.htmlA full tabbed demo of the engine
In practice
You type

Crates that stack up, and a cannon to knock them over.

What changes

Without the skill: boxes that jitter forever, sink into the ground, and explode when the tab is backgrounded.

With it: a World with gravity and a static floor, box bodies with friction and restitution, everything driven by world.update(dt) on a fixed step with interpolated rendering, and the cannon wired to world.raycast. The pile settles, stays settled, and goes to sleep.

Pairs with canvas-atelier. This is the "does it behave correctly" half. Soft connected motion — cloth, hair, rope — belongs to the Verlet approach in canvas-atelier. Simulate rigid bodies here, drape soft detail there.

03 — output style

caveman

Cuts the padding out of every reply and keeps all of the substance. Its own frontmatter claims a measured 65% reduction in output tokens.

The skill drops articles, filler ("just", "basically", "actually"), pleasantries and hedging, and allows fragments. What it explicitly refuses to touch is anything load-bearing: technical terms stay exact, code blocks are untouched, error strings are quoted verbatim, and API and CLI names are never abbreviated. It also refuses to invent abbreviations like cfg or impl — the tokenizer splits those the same as the full word, so they save nothing and cost the reader clarity.

It runs at four intensities plus classical-Chinese (wenyan) variants, preserves whatever language you wrote in, and — the part that makes it safe to leave on — it drops back to normal prose automatically for security warnings, irreversible action confirmations, and any multi-step sequence where dropped conjunctions would make the order ambiguous. Compression is never allowed to create doubt about whether to back up before dropping a table.

Live · same answer, four intensities
Question

Percentages are measured against the "off" answer with a rough token heuristic. Notice what survives all the way to ultra: useMemo, the actual cause, the actual fix. What disappears is everything that was never information.

What ships in the folder
  • SKILL.mdThe whole skill — rules, the six intensity levels, auto-clarity exceptions, worked examples. No scripts or references; this one is pure response style.
Stays on. The skill is explicit that it persists across turns rather than drifting back after a few replies. Turn it off with "stop caveman" or "normal mode".
Intensities
liteFull sentences and articles kept; filler and hedging gone. Professional but tight.
fullArticles dropped, fragments fine, short synonyms. The default.
ultraConjunctions stripped where cause and effect stay unambiguous. Each fact stated once.
wenyanClassical Chinese, in three depths — up to 80–90% character reduction.

04 — meta

matrix-agents-skill

Watches a session for knowledge worth keeping, and turns the best of it into a new skill. The machine that builds machines.

Every session creates knowledge and then throws it away: how a flow actually works, why one fix broke something else, which convention the project settled on. This skill runs quietly in the background of ordinary work, appending a line to a tally file after each completed task whenever it matches one of eleven patterns across five families — repetition, pain, exploration, decisions, and environment quirks. It writes the tally down rather than trying to remember, because attention decays over a long session and counts get lost.

The restraint is the design. It never interrupts mid-task; when a pattern crosses its threshold it emits exactly one line and keeps working. At the end it proposes at most one skill — the strongest candidate, ranked pain over exploration over decisions over repetition — and only if the result would save a future session real work. Say no and the topic goes in a declined.md it never raises again. Say yes and the gate opens onto a real interview (quick or deep), including the question that matters most: was anything here an exception that should not become the rule?

Live · a session in fast-forward

Real patterns and real thresholds from the skill's table. Four styling fixes trip pattern #1; two regressions in a row trip #4. Both are candidates, but only one gets proposed — pain outranks repetition, because knowledge bought with a regression saves the most time later.

What ships in the folder
  • SKILL.mdThe eleven-pattern table with thresholds, the interview question bank, the generated-skill format, and the routing-map block it maintains in CLAUDE.md
Creates two files as it runs, not shipped with it: session-tally.md (deleted after each proposal) and declined.md. It also delegates the actual writing to Anthropic's skill-creator skill when that's installed, rather than hand-rolling the format.
Why it registers what it builds
The routing map

A skill nobody routes to may as well not exist. After every skill it creates, it updates a delimited block in the project's CLAUDE.md — one line per skill, in the form "trigger condition → path".

Because CLAUDE.md loads in every session, that block guarantees a future session knows which skills exist without loading any of them.

Trigger words

/forge · /matrix · forge · matrix · פורג' · מטריקס

05 — transparency

skill-report

A one-line footer on every reply naming which skills, subagents and web tools actually ran — read from the transcript, not from Claude's memory of what it did.

Skills fire at Claude's discretion, which makes it genuinely hard to tell whether the one you installed did anything. This skill answers that question on every single turn. The detail that makes it trustworthy is where the answer comes from: a Stop hook reads the session transcript and extracts the real Skill, Agent, WebSearch and WebFetch calls. Asking Claude to recall its own tool use invites a confident, wrong answer; the transcript is ground truth.

A skill alone can't guarantee it fires every turn, so this one is paired with a hook that checks for the footer and forces one continuation if it's missing — which is why the report is unconditional rather than best-effort. Routine tools are deliberately excluded: Read, Edit, Bash and Grep run on nearly every turn, and listing them would turn signal into noise. The footer surfaces delegated capability.

Live · one turn, and the footer it produces

Greyed calls are the routine tools the hook ignores on purpose. Note the third turn: when nothing was delegated, the footer still appears and says none three times — an honest negative is the whole point.

What ships in the folder
  • SKILL.mdThe footer format and why a hook is required for it to be unconditional
  • scripts/report_hook.pyThe Stop hook — parses the transcript, finds this turn's real tool calls, forces a continuation when the footer is missing, and refuses to loop more than once
One extra step
Copying the folder is not enough for this one — the hook has to be registered in your project's .claude/settings.json. Merge this in, adding to an existing Stop array if you already have one. 
{
  "hooks": {
    "Stop": [
      { "hooks": [ { "type": "command",
        "command": "python \"$CLAUDE_PROJECT_DIR/.claude/skills/skill-report/scripts/report_hook.py\"",
        "timeout": 15 } ] }
    ]
  }
}
